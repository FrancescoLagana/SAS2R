SAS to R: Longitudinal Microdata Processing

A practical equivalence guide for within-individual calculations using data.table, dplyr, and base R

Author

Francesco Laganà

Published

November 6, 2026

1 Purpose and scope

This guide compares common SAS DATA-step patterns for longitudinal microdata with R implementations using data.table, dplyr, and base R. The emphasis is on calculations performed within individuals over time: ordering records, retaining values, identifying the first and last observation, comparing adjacent waves, constructing spells, detecting transitions, and summarising individual histories.

The examples use one row per individual and observation period, unless stated otherwise. Replace id, year, and the example variables with the names used in your production data.

library(data.table)
library(dplyr)

1.1 The central conceptual difference

A SAS DATA step processes observations sequentially. A RETAIN statement can carry a value from one iteration to the next, while FIRST.variable and LAST.variable are temporary indicators created by a BY statement.

In R, the same result is usually expressed by making the order explicit and then using one of these approaches:

  • data.table: setorder(), by = id, shift(), cum*() functions, and grouped expressions.
  • dplyr: arrange(), group_by(id), lag(), lead(), cum*() functions, and grouped expressions.
  • base R: order(), ave(), split()/lapply(), Reduce(), rle(), diff(), and explicit for loops when state matters.
  • Either package: an explicit stateful loop or a purpose-built function when the logic genuinely depends on a sequential state machine.

Most longitudinal tasks do not need a row-by-row loop in R. Grouped vector operations are generally clearer and faster. Base R can express all the same operations, though sometimes with more boilerplate.

2 Example data and ordering

DT <- data.table(
  id     = c(101, 101, 101, 102, 102, 103, 103, 103),
  year   = c(2020, 2021, 2023, 2020, 2022, 2019, 2020, 2021),
  status = c("A", "A", "B", "B", "B", "A", "B", "B"),
  income = c(3000, 3200, 3500, 2800, NA, 2500, 2700, 2900),
  weight = c(1.0, 1.1, 1.2, 0.9, 1.0, 1.0, 1.0, 1.0)
)

setorder(DT, id, year)
DT

Equivalent dplyr setup:

df <- DT |>
  as_tibble() |>
  arrange(id, year)

df

Equivalent base R setup (a plain data frame, kept alongside for later chunks):

df_base <- as.data.frame(DT)
df_base <- df_base[order(df_base$id, df_base$year), ]
rownames(df_base) <- NULL
df_base

Always define the ordering variable(s). SAS BY id year; depends on the data being sorted by those variables. In R, lag() and shift() use the current row order; they do not automatically sort data.

If ties are possible, add a deterministic tie-breaker, such as a wave number, interview date, or record sequence.

3 SAS BY, FIRST. and LAST.

3.1 What SAS creates

proc sort data=have;
  by id year;
run;

data want;
  set have;
  by id;
  if first.id then first_record = 1;
  else first_record = 0;

  if last.id then last_record = 1;
  else last_record = 0;
run;

FIRST.id is 1 on the first observation in each id group; LAST.id is 1 on the last. SAS also creates indicators for each variable in a multi-variable BY list. For by id year;, FIRST.year marks the first record for each id-year BY group, and FIRST.id also becomes 1 at the start of a new individual. The precise boundary behaviour follows the BY-group hierarchy.

3.2 data.table equivalent

DT[, `:=`(
  first_record = seq_len(.N) == 1L,
  last_record  = seq_len(.N) == .N
), by = id]

DT[, .(id, year, first_record, last_record)]

To mark first and last rows within each id-year group (usually meaningful only if there are additional records within a year):

DT[, `:=`(
  first_id_year = seq_len(.N) == 1L,
  last_id_year  = seq_len(.N) == .N
), by = .(id, year)]

DT[, c("id", "year", "first_id_year", "last_id_year"), with = FALSE]

3.3 dplyr equivalent

df <- DT |>
  as_tibble() |>
  arrange(id, year)

df
df <- df |>
  group_by(id) |>
  mutate(
    first_record = row_number() == 1L,
    last_record  = row_number() == n()
  ) |>
  ungroup()

Within an id-year group:

df |>
  group_by(id, year) |>
  mutate(
    first_id_year = row_number() == 1L,
    last_id_year  = row_number() == n()
  ) |>
  ungroup()

3.4 base R equivalent

Base R has no row_number()/.N inside a by=. Two common idioms:

  • ave() applies a function per group and returns a vector aligned with the rows. ave(seq_len(n), id, FUN = seq_along) gives the within-group position.
  • split() + lapply() + unsplit() / do.call(rbind, ...) gives explicit group handling.
df_base$first_record <- ave(seq_len(nrow(df_base)), df_base$id,
                            FUN = function(i) i == i[1])
df_base$last_record  <- ave(seq_len(nrow(df_base)), df_base$id,
                            FUN = function(i) i == i[length(i)])

df_base[, c("id", "year", "first_record", "last_record")]

Within id-year:

grp <- interaction(df_base$id, df_base$year, drop = TRUE)
df_base$first_id_year <- ave(seq_len(nrow(df_base)), grp,
                             FUN = function(i) i == i[1])
df_base$last_id_year  <- ave(seq_len(nrow(df_base)), grp,
                             FUN = function(i) i == i[length(i)])

df_base[, c("id", "year", "first_id_year", "last_id_year")]

ave() is the base R equivalent of “grouped mutate returning a vector”.

3.10 Equivalent of PROC SQL select *, max(var) as max_var ... group by id in R

DT <- data.table(
  id = c(1, 1, 1, 2, 2, 3),
  var = c(10, 20, 15, 5, 8, 12)
)

DT[, max_var := max(var), by = id]
DT

if you want only a line per group:

DT[, .(max_var = max(var)), by = id][]

These two last expressions seem similar, but they differ since the first one uses := that adds or updates columns in the original table, so the number of rows remains unchanged.

Consider this:

DT[, max_var := max(var), by = id]`

What happens?

  • by = id divides the data into groups.

  • max(var) calculates the maximum within each group.

  • := assigns that maximum to every row belonging to that group.

With DT[, .(max_var = max(var)), by = id]

What happens?

  • by = id divides the data into groups.

  • max(var) calculates the maximum within each group.

  • .() returns a result for each group.

  • data.table combines those results into a new table.

4 RETAIN: carry a value across observations

4.1 The SAS pattern

RETAIN prevents a DATA-step variable from being reset to missing at the start of each iteration. It is often used for previous values, running totals, state flags, and spell identifiers.

data want;
  set have;
  by id year;
  retain previous_income;

  if first.id then previous_income = .;
  else previous_income = lag(income);
run;

This particular example is not a robust general template: SAS LAG() is a queue function, not a simple “previous row” operator, and conditional calls can produce surprising results. For previous-row calculations, use a carefully controlled LAG() pattern or an explicit retained variable.

A direct retained-value pattern is:

data want;
  set have;
  by id year;
  retain previous_income;

  if first.id then previous_income = .;
  output;
  previous_income = income;
run;

The OUTPUT occurs before updating previous_income, so the output row contains the previous record’s value. If you want to update before output, change the order deliberately.

4.2 data.table: shift()

DT <- data.table(
  id     = c(101, 101, 101, 102, 102, 103, 103, 103),
  year   = c(2020, 2021, 2023, 2020, 2022, 2019, 2020, 2021),
  status = c("A", "A", "B", "B", "B", "A", "B", "B"),
  income = c(3000, 3200, 3500, 2800, NA, 2500, 2700, 2900),
  weight = c(1.0, 1.1, 1.2, 0.9, 1.0, 1.0, 1.0, 1.0)
)

setorder(DT, id, year)
DT
DT[, previous_income := shift(income), by = id]
DT[, c("id", "year", "income", "previous_income")]

By default, shift() returns the lagged value (n = 1, type = "lag"). The first row in each individual has NA. For the next observation:

DT[, next_income := shift(income, type = "lead"), by = id]
DT[, c("id", "year", "income", "previous_income", "next_income")]

4.3 dplyr: lag() and lead()

df |>
  group_by(id) |>
  mutate(
    previous_income = lag(income),
    next_income     = lead(income)
  ) |>
  ungroup() |> 
  select(id, year, income, previous_income, next_income)

4.4 base R: ave() with a custom shift, or manual indexing

Base R has no grouped shift()/lag(). The simplest base R idiom is ave() with a function that returns a padded vector:

shift_vec <- function(x, n = 1L, type = c("lag", "lead")) {
  type <- match.arg(type)
  len <- length(x)
  if (type == "lag") c(rep(NA, n), x[seq_len(len - n)]) else
                     c(x[-seq_len(n)], rep(NA, n))
}

df_base$previous_income <- ave(df_base$income, df_base$id,
                               FUN = shift_vec, n = 1L, type = "lag")
df_base$next_income     <- ave(df_base$income, df_base$id,
                               FUN = shift_vec, n = 1L, type = "lead")

df_base[, c("id", "year", "income", "previous_income", "next_income")]

ave() requires the function to return a vector of the same length as the group, which is why shift_vec pads with NA.

Mapping: a retained “previous observation” is usually a grouped shift() in data.table, grouped lag() in dplyr, or grouped ave(..., FUN = shift_vec) in base R. It is not necessary to reproduce SAS’s execution model literally.

5 Running totals and cumulative calculations

5.1 Running total within each individual

SAS:

data want;
  set have;
  by id;
  retain cumulative_income;
  if first.id then cumulative_income = 0;
  cumulative_income + income;
run;

The SAS sum statement cumulative_income + income; retains the accumulator and treats a missing summand as zero.

data.table:

DT[, cumulative_income := cumsum(fcoalesce(income, 0)), by = id]
DT[, .(id, year, income, cumulative_income)]

dplyr:

df |>
  group_by(id) |>
  mutate(cumulative_income = cumsum(coalesce(income, 0))) |>
  ungroup() |> 
  select(id, year, income, cumulative_income)

base R:

df_base$cumulative_income <- ave(df_base$income, df_base$id,
                                 FUN = function(x) cumsum(ifelse(is.na(x), 0, x)))
df_base[, c("id", "year", "income", "cumulative_income")]

ifelse(is.na(x), 0, x) is the base R equivalent of fcoalesce() / coalesce() for this purpose.

The missing-value treatment must be intentional. In R, cumsum(income) propagates NA from the first missing value onward. Use coalesce(income, 0) only if missing income should contribute zero. If missing means “unknown”, retain missingness or define a separate policy.

5.2 Running count of non-missing values

data.table:

DT[, n_income_observed := cumsum(!is.na(income)), by = id]

df |>

base R:

df_base$n_income_observed <- ave(df_base$income, df_base$id,

df_base[, c("id", "year",  "income", "n_income_observed")]

5.3 Running maximum or minimum

DT[, max_income_to_date := cummax(income), by = id]
DT[, min_income_to_date := cummin(income), by = id]
DT[, .(id, year, income, max_income_to_date, min_income_to_date)]
df |>
  group_by(id) |>
  mutate(
    max_income_to_date = cummax(income),
    min_income_to_date = cummin(income)
  ) |>

base R:

df_base$max_income_to_date <- ave(df_base$income, df_base$id, FUN = cummax)
df_base$min_income_to_date <- ave(df_base$income, df_base$id, FUN = cummin)
df_base[, c("id", "year", "max_income_to_date", "min_income_to_date")]

For numeric vectors containing missing values, decide how NA should affect the running statistic before using cummax() or cummin().

6 Comparing the current record with the previous record

6.1 Difference from previous wave

SAS:

data want;
  set have;
  by id year;
  retain previous_income;

  if first.id then change_income = .;
  else change_income = income - previous_income;

  previous_income = income;
run;

data.table:

DT[, change_income := income - shift(income), by = id]
DT[, .(id, year, income, previous_income, change_income)]

dplyr:

df |>
  group_by(id) |>
  mutate(change_income = income - lag(income)) |>
  ungroup() |> 
  select(id, year, income, change_income)

base R:

df_base$change_income <- ave(df_base$income, df_base$id,
                             FUN = function(x) x - shift_vec(x))
df_base[, c("id", "year", "income", "change_income")]

This compares adjacent records, not necessarily adjacent calendar years. For example, 2021 to 2023 is a two-year gap. If you need year-to-year change only when years are consecutive:

DT[, change_income_annual := fifelse(
  year - shift(year) == 1L,
  income - shift(income),
  NA_real_
), by = id]

DT[, .(id, year, income, previous_income, change_income_annual)]
df |>
  group_by(id) |>
  mutate(
    change_income_annual = if_else(
      year - lag(year) == 1L,
      income - lag(income),
      NA_real_,
      missing = NA_real_
    )
  ) |>
  ungroup()

base R:

df_base$change_income_annual <- ave(
  df_base$income,
  df_base$id,
  FUN = function(x) {
    prev_income <- shift_vec(x)
    prev_year   <- shift_vec(df_base$year[match(seq_along(x), seq_along(x))])
    NA_real_
  }
)
# Simpler and clearer for base R: split, compute, recombine
df_base$change_income_annual <- NA_real_
for (i in unique(df_base$id)) {
  idx <- which(df_base$id == i)
  yrs <- df_base$year[idx]
  inc <- df_base$income[idx]
  chg <- rep(NA_real_, length(idx))
  if (length(idx) > 1L) {
    consecutive <- (yrs[-1] - yrs[-length(yrs)]) == 1L
    chg[-1] <- ifelse(consecutive, inc[-1] - inc[-length(inc)], NA_real_)
  }
  df_base$change_income_annual[idx] <- chg
}
df_base[, c("id", "year", "income", "change_income_annual")]

6.2 Flag a change in categorical status

SAS:

data want;
  set have;
  by id year;
  retain previous_status;

  if first.id then status_changed = 0;
  else status_changed = (status ne previous_status);

  previous_status = status;
run;

data.table:

DT[, status_changed := !is.na(shift(status)) & status != shift(status), by = id]

DT[, .(id, year, status, status_changed)]

dplyr:

df |>
  group_by(id) |>
  mutate(status_changed = !is.na(lag(status)) & status != lag(status)) |>
  ungroup()

base R:

df_base$status_changed <- ave(df_base$status, df_base$id, FUN = function(x) {
  prev <- shift_vec(x)
  !is.na(prev) & !is.na(x) & x != prev
})
df_base[, c("id", "year", "status", "status_changed")]

This treats the first record as “not changed”. If the first record should instead be unknown, use NA for the first row. Also decide how to handle missing status: a transition from missing to observed may be meaningful or may be classified as unknown.

7 Detecting first occurrence, last occurrence, and extrema

7.1 First observed non-missing value per individual

data.table:

DT[, first_observed_income := {
  x <- income[!is.na(income)]
  if (length(x)) x[1L] else NA_real_
}, by = id]
DT[, .(id, year, income, first_observed_income)]

This data.table syntax in R creates a new column called first_observed_income that stores the very first non-missing (NA) income value for each individual (id).

Here is the step-by-step breakdown of how it works:

  • DT[, ... , by = id]: This groups the data by the id column. The code inside the braces {} is executed separately for each unique ID.

  • first_observed_income :=: The := operator adds (or updates) the column in-place without copying the entire data frame in memory.

  • x <- income[!is.na(income)]: Inside the group, it filters out all NA values from the income column and assigns the remaining valid incomes to a temporary variable x.

  • if (length(x)) x[1L] else NA_real_:

    • If x contains at least one valid income (length(x) > 0), it extracts the first one (x[1L]).

    • If all income values for that ID are NA (meaning length(x) is 0), it returns a missing value typed specifically for numeric data (NA_real_).

Much easier:

DT[, first_observed_income := fcoalesce(as.numeric(income))[1L], by = id]
DT[, .(id, year, income, first_observed_income)]

This piece of code uses the { in j`. In data.table, {} allows you to write a sequence of R expressions inside j.

DT[, result := {
  a <- mean(income, na.rm = TRUE)
  b <- max(income, na.rm = TRUE)
  a + b
}, by = id]

DT

dplyr:

df |>
  group_by(id) |>
  mutate(
    first_observed_income = {
      x <- income[!is.na(income)]
      if (length(x)) x[1L] else NA_real_
    }
  ) |>
  ungroup()

base R:

first_nonmissing <- function(x) {
  x <- x[!is.na(x)]
  if (length(x)) x[1L] else NA_real_
}
df_base$first_observed_income <- ave(df_base$income, df_base$id,
                                     FUN = first_nonmissing)
df_base[, c("id", "year", "income", "first_observed_income")]

This repeats the first observed income on every row for that individual. To keep only the value on the first row, combine it with first_record.

7.2 First year with a condition

For example, the first year in which status becomes "B":

DT[, first_year_B := {
  y <- year[status == "B"]
  if (length(y)) min(y) else NA_integer_
}, by = id]

DT[, .(id, year, status, first_year_B)]

It combines three concepts:

  • by = id: performs the calculation separately for each individual.

  • {}: allows multiple R expressions inside j.

  • :=: creates or updates a column in the original data.table.

Step 1: Select the years when status is B

y <- year[status == "B"]

This is a logical filter.

For example, suppose an individual has:

year status
2019 A
2020 B
2021 A
2022 B

The condition:

status == "B"

returns:

FALSE TRUE FALSE TRUE

Consequently:

y <- year[status == "B"]

returns:

y
# 2020 2022

Step 2: Check whether any B observations exist

if (length(y))

Checks whether the vector y contains at least one observation.

  • If length(y) > 0, calculate the minimum year.

  • If length(y) == 0, return a missing value.

Step 3: Find the earliest year

min(y)

Returns the smallest year.

For example:

min(c(2020, 2022))
# 2020

Step 4: Handle individuals without status B

else NA_integer_

If an individual never has status B, the result is NA_integer_.

This is a missing value of integer type.

7.2.1 3. Complete example

Consider this dataset:

DT <- data.table(
  id = c(1, 1, 1, 2, 2, 2, 3, 3),
  year = c(2019, 2020, 2021, 2019, 2020, 2021, 2020, 2021),
  status = c("A", "B", "A", "A", "A", "B", "A", "A")
)

Execute:

DT[, first_year_B := {
  y <- year[status == "B"]
  if (length(y)) min(y) else NA_integer_
}, by = id]

Result:

id year status first_year_B
1 2019 A 2020
1 2020 B 2020
1 2021 A 2020
2 2019 A 2021
2 2020 A 2021
2 2021 B 2021
3 2020 A NA
3 2021 A NA

Notice that the result is repeated across all observations belonging to the same individual.

7.2.2 4. Why use min(y) instead of y[1L]?

This is an important distinction.

  • y[1L] returns the first year in the current row order.

  • min(y) returns the chronologically earliest year, regardless of row order.

For example:

y <- c(2022L, 2020L, 2021L)

y[1L]
# 2022

min(y)
# 2020

If your data are not sorted chronologically, min(y) is safer.

7.2.3 5. A more concise alternative

You could also write:

DT[, first_year_B := {
  y <- year[status == "B"]
  if (any(status == "B")) min(y) else NA_integer_
}, by = id]

Both approaches work, but the original code is perfectly valid.

Key takeaway: the code performs a grouped conditional calculation: select the years corresponding to status B, find the earliest one, and assign it to every observation of the same individual. If no B exists, assign NA.

  ungroup()

8 Constructing spells and episodes

Longitudinal microdata often contain spells: consecutive observations during which a condition remains true, or periods in which a categorical state does not change.

8.1 Start a new spell whenever status changes

SAS:

data want;
  set have;
  by id year;
  retain spell_id previous_status;

  if first.id then do;
    spell_id = 1;
    previous_status = status;
  end;
  else do;
    if status ne previous_status then spell_id + 1;
    previous_status = status;
  end;
run;

data.table:

DT[, spell_start := seq_len(.N) == 1L | status != shift(status), by = id]
DT[, spell_id := cumsum(spell_start), by = id]
DT

dplyr:

  group_by(id) |>
  mutate(

base R:

df_base$spell_start <- ave(seq_len(nrow(df_base)), df_base$id, FUN = function(i) {

                        FUN = function(i) cumsum(df_base$spell_start[i]))

The examples assume status is not missing. When status can be missing, define whether two missing statuses count as the same state, and whether transitions into or out of missing values start a new spell. In R, NA != "A" evaluates to NA, so the expression must be adapted to your missing-value policy.

A missing-safe version that treats two missing values as the same state can use an explicit comparison helper:

same_state <- function(x, y) {
  (is.na(x) & is.na(y)) | (!is.na(x) & !is.na(y) & x == y)
}

DT[, spell_start := {
  previous <- shift(status)
  seq <- seq_len(.N)
  seq == 1L | !same_state(status, previous)
}, by = id]
DT[, spell_id := cumsum(spell_start), by = id]

For character variables this helper is straightforward. For more complex types, adapt the comparison carefully.

11 Conditional carry-forward and last observation carried forward

A common SAS pattern uses RETAIN to carry the most recent observed value forward.

SAS:

data want;
  set have;
  by id year;
  retain carried_status;

  if first.id then carried_status = status;
  else if not missing(status) then carried_status = status;
run;

This requires a policy for a missing value in the first row of each individual. A clear R implementation is to fill missing values within each individual after sorting.

data.table:

#DT[, carried_status := nafill(status, type = "locf"), by = id]
setorder(DT, id, year)

DT[, carried_status := {
  codes <- match(status, unique(status[!is.na(status)]))
  codes <- nafill(codes, type = "locf")
  unique(status[!is.na(status)])[codes]
}, by = id]

DT[, .(id, year, status, carried_status)]

For character data, support for nafill() depends on the data.table version and type. A broadly applicable alternative is to use zoo::na.locf() (with na.rm = FALSE) or an explicit grouped fill operation.

EXPLANATION OF THE CODE:

11.0.1 1. Create numeric codes

codes <- match(status, unique(status[!is.na(status)]))

Suppose status contains:

status
A 1
A 1
NA NA
B 2
NA NA
C 3

  • status[!is.na(status)] removes missing values.

  • unique() keeps each distinct status once: A, B, C.

  • match() assigns each observation its position in that vector.

So codes becomes:

1 1 NA 2 NA 3

11.0.2 2. Carry forward the numeric codes

codes <- nafill(codes, type = "locf")

nafill() fills each missing value with the preceding non-missing value.

Result:

1 1 1 2 2 3

11.0.3 3. Restore the original status values

unique(status[!is.na(status)])[codes]

This uses the numeric codes as indexes into the original vector of distinct status values:

c("A", "B", "C")[c(1, 1, 1, 2, 2, 3)]

Result:

"A" "A" "A" "B" "B" "C"

11.0.4 4. Why by = id?

by = id

All three operations are performed separately for each id. The carry-forward therefore never crosses from one individual to another.

In short: numeric encoding → LOCF → restore original labels.

One important detail: this expression assumes that status contains actual NA values and that the observations are sorted by id and year. Leading missing values remain missing, as in your SAS code.

dplyr:

# Requires tidyr
# library(tidyr)
df |>
  group_by(id) |>
  tidyr::fill(status, .direction = "down") |>
  ungroup()

base R:

locf <- function(x) {
  last  <- NA
  for (i in seq_along(x)) {
    if (!is.na(x[i])) last <- x[i]
    x[i] <- last
  }
  x
}
df_base$carried_status <- ave(df_base$status, df_base$id, FUN = locf)
df_base[, c("id", "year", "status", "carried_status")]

locf() is a small explicit loop, which is idiomatic base R for this kind of sequential fill. It respects the sorted row order and does not fill leading missing values.

This fills only downward within each individual’s sorted history. It does not fill leading missing values unless you also use an upward fill, which changes the meaning and should be justified.

13 Multi-row state logic: when a loop is appropriate

Most tasks above are best expressed with vectorised grouped operations. A loop may be appropriate when each row’s result depends on a complex state updated by several rules, such as an eligibility state machine or a sequential imputation algorithm.

A base R example of a running balance with a reset condition:

calculate_balance <- function(amount, reset) {
  out <- numeric(length(amount))
  balance <- 0

  for (i in seq_along(amount)) {
    if (isTRUE(reset[i])) balance <- 0
    if (!is.na(amount[i])) balance <- balance + amount[i]
    out[i] <- balance
  }
  out
}

DT[, balance := calculate_balance(income, reset = status == "A"), by = id]

DT[, .(id, year, income, status, balance)]

The input to calculate_balance() must already be in chronological order. For missing status, reset = status == "A" can contain NA; the use of isTRUE() inside the function makes an NA reset behave as false. Confirm that this is the intended business rule.

Questo codice R calcola un saldo progressivo (o cumulo) del reddito per ogni id, con la particolarità che questo saldo viene azzerato (riportato a 0) ogni volta che la colonna status è uguale a “A”.

Much more efficiently by using pure data.table syntax and eliminating the for loop entirely. The for loop in your original R function processes data row by row, which becomes very slow on large datasets.

The optimal approach is to create temporary sub-groups that increment every time status == "A" occurs, and then apply R’s highly optimized, built-in cumsum() function within those sub-groups.

Here is the fastest and most idiomatic data.table way to do it:

# 1. Create a temporary sub-group ID for each reset block within each id
DT[, grp_reset := cumsum(status == "A"), by = id]

# 2. Calculate the cumulative sum grouped by both id and the reset block
DT[, balance := cumsum(fifelse(is.na(income), 0, income)), by = .(id, grp_reset)]

# 3. Clean up the temporary grouping column
DT[, grp_reset := NULL]

DT[, .(id, year, income, status, balance)]

Why this approach is better

  • Speed: Both cumsum() and fifelse() are compiled in C, making them exponentially faster than a standard R for loop.

  • Memory Efficiency: It leverages data.table’s internal grouping optimizations (by = .(id, grp_reset)) without making memory copies of the data.

  • Safe NA Handling: The fifelse() function temporarily replaces NA values with 0 strictly for the mathematical sum, ensuring NA rows don’t break the chain while leaving your original income column unchanged.

A dplyr version can call the same function on each group:

df |>
  group_by(id) |>
  mutate(balance = calculate_balance(income, reset = status == "A")) |>
  ungroup()

A pure base R version applies the same function by id with ave():

df_base$balance <- ave(df_base$income, df_base$id, FUN = function(x) {
  idx <- which(df_base$id == df_base$id[which(df_base$income == x[1])][1])
  # clearer alternative below
  x
})
# Clear base R implementation: split by id, apply, unsplit
df_base$balance <- NA_real_
for (i in unique(df_base$id)) {
  idx <- which(df_base$id == i)
  df_base$balance[idx] <- calculate_balance(
    df_base$income[idx],
    reset = df_base$status[idx] == "A"
  )
}
df_base[, c("id", "year", "income", "status", "balance")]

Avoid translating every SAS DATA step into an explicit R loop. Use a loop when the algorithm is inherently sequential; otherwise prefer grouped vector operations.

create_panel <- function(dt, id_col, from_col = "year_from", to_col = "year_to") {

17 Important migration pitfalls

17.1 SAS missing values are not identical to R NA

In R, comparisons involving NA often return NA, not TRUE or FALSE. For example:

NA != "A"
[1] NA

This is NA, so a condition based on it may propagate missingness. In SAS, missing values participate in comparisons under SAS’s own ordering rules. Never assume that a direct translation of a SAS condition has identical behaviour.

Write the intended missing-value policy explicitly, for example:

!is.na(status) & status == "B"

or use a missing-safe equality helper if two missing values should be considered equal.

17.2 SAS sum statements and R cumulative sums differ

The SAS sum statement retains the accumulator and ignores a missing addend. R’s cumsum() propagates NA. To mimic the SAS sum statement, use coalesce(x, 0) only if that is the intended interpretation of missing data.

17.3 LAG() is a SAS queue function

A SAS LAG(x) call retrieves a value from a queue populated when that function executes. If it is called conditionally, the queue advances only when the call executes. This can differ from a simple previous-row operation. In R, grouped lag() and shift() are positional within the group and are generally more transparent.

17.4 FIRST. and LAST. are BY-group flags, not data values

They are created by SAS from the BY statement and sort order. In R, create flags from row_number() or seq_len(.N) after ordering. Do not assume the source file is already sorted.

17.5 Duplicate keys require a decision

If an individual has multiple records in the same year, decide whether the longitudinal unit is id-year, whether duplicates should be resolved, or whether a second ordering variable is needed. FIRST.id still identifies the first row of an individual, but “previous year” logic may be ambiguous.

17.6 Grouping state is different

data.table groups a calculation through by= for that expression. dplyr::group_by() changes the grouping metadata of the object until it is modified or removed with ungroup(). Unintended persistent grouping is a common source of errors. Base R ave() and split() create grouping only for the duration of the call and leave no persistent state.

17.7 Avoid modifying shared objects unintentionally

data.table uses reference semantics for operations such as :=; it may modify DT in place. If a separate copy is needed:

DT_work <- copy(DT)

With dplyr, verbs generally return a new object, although assignment can replace the previous object. Base R functions in this guide return new objects and do not modify their inputs.

18 A recommended template for production code

A robust longitudinal workflow should make the key assumptions visible.

The examples below use input_data as a placeholder for the table you are processing; here it is aliased to DT so that the chunks run.

input_data <- DT

18.1 data.table template

DT <- as.data.table(copy(input_data))
setorder(DT, id, year)

# One-row-per-person-period validation
duplicates <- DT[, .N, by = .(id, year)][N > 1L]
if (nrow(duplicates) > 0L) {
  stop("Duplicate id-year records: resolve before longitudinal calculations.")
}

DT[, `:=`(
  first_record    = seq_len(.N) == 1L,
  last_record     = seq_len(.N) == .N,
  previous_status = shift(status),
  previous_income = shift(income)
), by = id]

DT[, status_changed := {
  prev <- shift(status)
  !is.na(prev) & !is.na(status) & status != prev
}, by = id]

DT[, cumulative_income := cumsum(fcoalesce(income, 0)), by = id]

18.2 dplyr template

df <- input_data |>
  as_tibble() |>
  arrange(id, year)

duplicates <- df |>
  count(id, year, name = "n") |>
  filter(n > 1L)

if (nrow(duplicates) > 0L) {
  stop("Duplicate id-year records: resolve before longitudinal calculations.")
}

df <- df |>
  group_by(id) |>
  mutate(
    first_record    = row_number() == 1L,
    last_record     = row_number() == n(),
    previous_status = lag(status),
    previous_income = lag(income),
    status_changed  = !is.na(previous_status) &
      !is.na(status) & status != previous_status,
    cumulative_income = cumsum(coalesce(income, 0))
  ) |>
  ungroup()

18.3 base R template

df_base <- as.data.frame(input_data)
df_base <- df_base[order(df_base$id, df_base$year), ]
rownames(df_base) <- NULL

# One-row-per-person-period validation
dup_keys <- paste(df_base$id, df_base$year, sep = "_")
if (anyDuplicated(dup_keys)) {
  stop("Duplicate id-year records: resolve before longitudinal calculations.")
}

df_base$first_record    <- ave(seq_len(nrow(df_base)), df_base$id,
                               FUN = function(i) i == i[1])
df_base$last_record     <- ave(seq_len(nrow(df_base)), df_base$id,
                               FUN = function(i) i == i[length(i)])
df_base$previous_status <- ave(df_base$status, df_base$id,
                               FUN = function(x) shift_vec(x))
df_base$previous_income <- ave(df_base$income, df_base$id,
                               FUN = function(x) shift_vec(x))
df_base$status_changed  <- !is.na(df_base$previous_status) &
  !is.na(df_base$status) &
  df_base$status != df_base$previous_status
df_base$cumulative_income <- ave(df_base$income, df_base$id,
                                 FUN = function(x) cumsum(ifelse(is.na(x), 0, x)))

The three templates intentionally make missing-value behaviour explicit for status_changed. The cumulative income examples treat missing income as zero; change this if missingness means unknown rather than zero.

For very large longitudinal microdata, data.table is often a strong default when memory efficiency and speed are important. dplyr is also a sound choice when the team prefers a declarative pipeline and the data volume and execution environment support it. Base R has no external dependencies and is sufficient for many tasks, but grouped operations quickly become verbose, and the SAS-style sequential state patterns (RETAIN, LAG) usually require an explicit loop. All three can express most RETAIN and FIRST./LAST. use cases without translating SAS’s row-by-row mechanics literally.

20 Final checklist

Before going to SAS-to-R longitudinal migration, verify:

  1. Is the data sorted by the same variables as the SAS BY statement?
  2. Are duplicate individual-period records possible, and how are they handled?
  3. Does “previous observation” mean previous record or previous calendar period?
  4. What should happen on the first record for an individual?
  5. Are missing values ignored, propagated, treated as zero, or treated as a separate state?
  6. Does the SAS code use LAG() conditionally?
  7. Does a spell break on a status change, a time gap, or both?
  8. Does the output contain one row per individual, one row per individual-period, or one row per spell?
  9. Are multiple SAS output datasets best represented by multiple named R objects?
  10. Have results been validated against SAS on a representative sample, including edge cases?

A good migration reproduces the business meaning of the SAS logic, not merely its syntax. For longitudinal microdata, ordering, missing-value policy, and the definition of an observation are usually the most consequential decisions.
